# 开发项目的文档与任务连续性

- 需要持续维护或跨会话交接，且涉及多模块、外部服务或部署、分阶段交付、复杂业务约束之一的开发项目，应维护下列文档职责；一次性小改动不必补齐整套文件。
- 优先复用现有文档、命名与目录。README 负责用途、入口和操作；SPEC 负责现行行为、契约和验收标准；CHANGELOG 记录重要变化及发布状态；TASK 记录当前任务、未完成项、阻塞和下一步；CASE-STUDY 沉淀真实错误的证据、原因、修复验证和复用经验。
- 文档可以是单个 Markdown，也可以按模块或主题拆为带索引的目录。案例较多时使用 `case-study/`（或已有等价目录），每个案例一个 Markdown，以目录内 README 或既有索引导航；没有实际案例时不虚构。
- 开工读取相关文档，变更时只更新受影响内容；结束、暂停或交接前，将未完成事项写回任务入口，不只留在聊天里。
- 同一事实或状态只维护一个权威来源，其他位置链接引用；区分现行规格、未实现方案、历史记录，以及实现、验证、发布和运行验收，不把局部成功当作全部完成。
- 文档同步不扩大操作权限，也不得把凭据或内部记录混入公开产物。
