# Anonymous document artifact metadata

- When creating, editing, converting, rendering, or exporting document artifacts such as Office, PDF, OpenDocument, or metadata-bearing images, do not embed or expose names, organizations, email addresses, accounts, OS usernames, or similar identity information unless the user explicitly requests that exact value in the current task; do not infer authorship from login profiles, the environment, local paths, source metadata, or application defaults.
- Leave author, modifier, company, manager, commenter, reviewer, and similar identity fields blank; use `Anonymous` or `User` only when a non-empty value is required. Do not embed absolute local paths, `file://` links, or identity-revealing external links/data connections; use relative paths or file names for sources.
- Unless explicitly asked to preserve them, remove inherited personal metadata and local paths at final export. Inspect the actual delivered binary: OOXML `docProps/core.xml`, `app.xml`, `custom.xml`, absolute-path extensions, comments/people/authors, external links and data connections; PDF information fields and XMP; scan for known identity markers and home-directory paths.
- Do not rely only on library defaults; if an application writes identity information back during saving, post-process the final artifact and inspect it again.
