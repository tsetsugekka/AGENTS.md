# 前端设计规则

仅用于界面设计、改版及涉及界面的前端开发；纯后台、数据、文档或其他非界面任务不读取。本文件为设计偏好的唯一详细来源，不复制到三个 Skill 中。

## Skill 分工

- 从零创建页面优先用 `finesse-ui`：先明确页面用途、目标风格与不想要的效果，简述设计方向，确认后实现；后续反馈优先局部调整。
- 既有页面改版优先用 Taste 套件的 `redesign-existing-projects`（目录 `redesign-skill`）：先确认保留项、目标风格及改动范围，再调整版面、动效与信息密度，保留未要求改变的功能。
- 设计实现后用 `impeccable audit` 检查，再针对实际问题按需 `polish` 收尾；不把审计当成修改授权，不反复审计或无止境打磨。
- 这是默认分工，不是每次必跑三套的流水线；按任务阶段只读所需 Skill 与参考资料。用户明确指定、项目既有设计系统及局部改动范围优先，不机械叠加相互冲突的风格规则。

## 信息密度

- PC 和手机界面默认尽量 compact：先收紧页面本身的留白、内外边距、行高、模块尺寸和重复说明，在文字可读、层级清楚、点击与触控可靠的前提下提高信息密度。同类模块保持一致的尺寸与间距。
- compact 不等于把内容折叠或藏进按钮。先优化默认可见页面；是否隐藏次要内容按页面用途、使用频率和内容重要程度判断，核心信息与主要操作直接可见。
- App 式导航不能代替区块内部的紧凑设计。设置页、筛选、表格、选项和空态同样收紧；避免为触控高度叠加多层 padding、margin 和大空白卡片，视觉尺寸与操作区域一起核验。

## 手机按 App 的使用流程设计

- 先确定手机上最常做的事，再组织首屏、导航和操作路径；从手机的可用空间重新安排内容，不能只把桌面多列堆成一条长页面或等比例缩小。
- 看行情的页面优先呈现当前标的、关键数值、常用切换和图表；管理、设置及低频说明按用途进入明确的工作区。只有内容与频率确实需要时才采用底部导航，不机械套用同一套标签或藏起主要功能。
- 高频切换要在窄屏直接可用；少量标的可采用等宽代码按钮，将名称、价格和状态集中到当前标的详情，避免每个切换项重复大块内容。按实际最大数量测试，不能只用一个项目判断布局。
- 保持与 PC 一致的品牌、字体、颜色、控件语言和业务含义；手机可以调整内容顺序、导航与操作位置，维持当前选择和状态连续性。仅手机范围的改版不改变 PC 布局或数据逻辑。
- 在真实窄屏尺寸核验核心操作、长名称、最大列表数量、空态、加载／错误、滚动与固定栏遮挡；不能只凭 CSS 或截图宣称交互通过。桌面同时检查，确认手机改动没有外溢。
