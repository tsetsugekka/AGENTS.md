# 前端设计规则

仅用于界面设计、改版、涉及界面的前端开发及网页 SEO／分享预览任务；按相关章节读取，纯后台、数据、文档或其他无关任务不读取。本文件为设计偏好的唯一详细来源，不复制到三个设计 Skill 中。

## Skill 分工

- 从零创建页面优先用 `finesse-ui`：先明确页面用途、目标风格与不想要的效果，简述设计方向，确认后实现；后续反馈优先局部调整。
- 既有页面改版优先用 Taste 套件的 `redesign-existing-projects`（目录 `redesign-skill`）：先确认保留项、目标风格及改动范围，再调整版面、动效与信息密度，保留未要求改变的功能。
- 设计实现后用 `impeccable audit` 检查，再针对实际问题按需 `polish` 收尾；不把审计当成修改授权，不反复审计或无止境打磨。
- 这是默认分工，不是每次必跑三套的流水线；按任务阶段只读所需 Skill 与参考资料。用户明确指定、项目既有设计系统及局部改动范围优先，不机械叠加相互冲突的风格规则。

Skill 来源：[finesse-ui](https://github.com/mouse-lin/finesse-skill)、[redesign-existing-projects](https://github.com/Leonxlnx/taste-skill)、[impeccable](https://github.com/pbakaus/impeccable)。按各作者的当前安装说明准备实际使用环境；这些规则不代替 Skill 正文，也不代表已安装。

## 信息密度

- PC 和手机界面默认尽量 compact：先收紧页面本身的留白、内外边距、行高、模块尺寸和重复说明，在文字可读、层级清楚、点击与触控可靠的前提下提高信息密度。同类模块保持一致的尺寸与间距。
- compact 不等于把内容折叠或藏进按钮。先优化默认可见页面；是否隐藏次要内容按页面用途、使用频率和内容重要程度判断，核心信息与主要操作直接可见。
- 先明确页面的核心内容，并让它进入默认首屏：图表页先看到实际图表，不能让标题、状态、入口、选项卡、筛选和说明占满首屏。PC 同样遵循内容优先，手机约束更严格；只保留读懂核心内容所需的前置信息与紧凑高频控件，其余安排在内容之后或对应工作区。按常见手机视口的实际内容位置验收，不以“有图表入口”代替图表已可见。
- App 式导航不能代替区块内部的紧凑设计。设置页、筛选、表格、选项和空态同样收紧；避免为触控高度叠加多层 padding、margin 和大空白卡片，视觉尺寸与操作区域一起核验。
- 手机摘要、列表和空态取消无用途的桌面最小高度，由真实内容撑高；短摘要不能占满大卡片，长摘要也不压进过窄的多列。日期、保存期限和数量等说明采用紧凑文字，避免伪装成大按钮。
- 普通按钮、输入框和选择器采用一致的紧凑尺寸；输入代码等短值不继承行情标题的大字号。选中、禁用与未选中控件都检查实际高度和四周留白，不能只压缩容器。图例、缩放滑杆、指标摘要也检查行距、标签与数值间距及容器留白，避免辅助信息比内容占用更多空间。
- 卡片辅助信息按稳定的逻辑行组织，统计项可等分铺满可用宽度；紧凑品牌图形能表达含义时可省去重复文字，同时保留完整可访问名称。核验标签一行／多行、三位数选择值和最长选项；检查最终计算尺寸及父子间距叠加，不能只看新增 CSS 数值。
- 固定列的日程表、矩阵按最长真实条目检查：分组标题保持单行，必要时省略并保留完整可访问名称；任务正文与状态允许自然换行，由内容撑高整行，日期格同步同高，不能用固定行高挤出或遮住状态。手机输入框与原生选择器优先保持 16px 输入字号，通过控件高度及内边距收紧，避免 iOS 聚焦放大。
- 数据表格与矩阵优先铺满可用宽度，按最长真实标签、单位和合理数字位数确定列宽；内容稀疏时允许继续收窄，不过早横向滚动，也不为极端值预留大片空白。需要滚动时只在表格内部滚动。密集证券列表先代码后名称，代码列采用可覆盖实际市场格式的一致宽度，名称与后续内容按列对齐。行合计放在名称及对应可视化条附近，并与每日／每周数据视觉隔离。
- 密集列表的标签采用单行时，溢出内容在本行内查看，不换行撑高条目；触摸可直接横向查看，指针 hover 滚动只作用于实际溢出的标签。右侧数值与操作保持可见，完整标签仍可访问。

## 手机按 App 的使用流程设计

- 先确定手机上最常做的事，再组织首屏、导航和操作路径；从手机的可用空间重新安排内容，不能只把桌面多列堆成一条长页面或等比例缩小。
- 底栏本身就是导航，应按主要业务内容或高频操作分组；不要让低频使用说明或重复目录单独占一个 Tab。底栏加组内少量短切换已经能完成定位，次要指南放在内容之后或默认收起，不为凑入口拆出工作区。已有底栏入口时，移除手机正文或右上角重复的同一入口。
- 同一业务的多个页面可共用一套手机底栏，让入口顺序、名称、图标与选中态连续；各页面保留真实URL，跨页项使用链接，按业务内容命名，不使用Model1等内部编号。
- 决定用户能否开始使用或切换到自己数据的关键引导（如上传交易记录）保持醒目。原先默认展开的引导保留默认可见性，可由用户显式收起为底栏上方的小入口并再次展开，不能在紧凑改版中只剩难发现的角落按钮。
- 第二层选单只用于确有需要的低频、次要功能；入口名称须能提示内容，评估路径加深带来的发现率下降。核心内容直接进入；独立专题页不自动作为主工具的功能入口，也不强制套用底栏。
- 相关内容较短、适合连续阅读时，优先同一工作区上下滚动，不为区分两块内容增加二级Tab。语言或权限特有入口移除后，其他用户的导航仍须有实际用途；按各可见入口组合验收，必要时允许独立窄图标项，保持栏高和视觉语言一致。
- 看行情的页面优先呈现当前标的、关键数值、常用切换和图表；管理、设置及低频说明按用途进入明确的工作区。只有内容与频率确实需要时才采用底部导航，不机械套用同一套标签或藏起主要功能。
- 高频切换要在窄屏直接可用；少量标的可采用等宽代码按钮，将名称、价格和状态集中到当前标的详情，避免每个切换项重复大块内容。按实际最大数量测试，不能只用一个项目判断布局。
- 手机文案按操作目的精简，筛选入口、周期和标签不必照搬桌面全量文字；保留业务含义、当前选择和必要说明，完整名称仍可在展开内容或可访问名称中读取。少量筛选优先同排，展开菜单可占更宽空间，不把选项一起压窄。
- 同一层的筛选采用一致的选择器行为，显示类别、当前值与展开箭头；图／表等显示方式合为一个选择器，不与周期、市场选择器并列成两个页面Tab。底栏可用短名，正文栏目标题保留完整业务名称，避免误改内容定位。
- 手机新闻列表的缩略图与所属文字并排，通常文字在左、图在右，从时间／标签行的顶部对齐，避免图片上方留一整行空白；没有图片的条目使用整行。核验短正文、长正文和长图，不能把小图单独放在正文下方而留下大块空白；图片查看入口保持可用。
- 手机快捷入口优先采用当前语言中易辨认的短名，内部代码保留在详情或数据契约中。短名必须对应真实对象，不能为好认而把综合指数改称其他指数或期货；文档链接可简写可见路径，但保留完整地址、锚点和正文。
- 参考截图先明确用户指定的借鉴范围，例如只参考坐标轴字号，就只调整对应部分；未经要求不连带替换整页布局、品牌或内容结构。压缩说明区时保留原有视觉层级与辨识特征。
- 保持与 PC 一致的品牌、字体、颜色、控件语言和业务含义；手机可以调整内容顺序、导航与操作位置，维持当前选择和状态连续性。仅手机范围的改版不改变 PC 布局或数据逻辑。
- 在真实窄屏尺寸核验核心操作、长名称、最大列表数量、空态、加载／错误、滚动与固定栏遮挡；不能只凭 CSS 或截图宣称交互通过。桌面同时检查，确认手机改动没有外溢。
- 手机拥有独立列表工作区时，按阅读用途重新评估可见条数，不直接沿用桌面为排版设定的上限。区分数据源条数、前端筛选与显示上限，保留该列表既有的排序与筛选口径；需要调整数据源时按其消费者契约处理。
- 手机改版同时复核实际加载图：CSS隐藏并不延后请求或解析。检查首屏与切换工作区时的请求、非首屏内容是否按需加载、压缩编码及缓存；区分传输字节、解压后体积和运行开销，不能把文件变小写成实际加载耗时已经降低。改变生产数据投影或生成器时另行核对消费者契约。
- 浏览器参考与验收优先复用已有任务标签，检查结束即关闭本轮不再使用的标签；不积累测试页面，也不关闭用户或其他任务正在使用的页面。
- 用户指正的共性问题随修复沉淀为本文件中的可执行检查项，页面特有行为记入项目规格。后续处理其他页面时主动核查这些问题；只记录实际反馈和验证结论，不把一次修复扩成重复的经验清单。

## 共享交互语言与图表空间

- 同一项目的Header、Footer、Sidebar与手机底部导航属于同一套设计语言。修改共享组件时核对全部实际消费者的影响范围，不只检查当前页面。底栏按实际主要内容设置入口，不凑数量；栏高、安全区、图标尺寸、标签、选中态和控件风格统一。同义图标复用同一个定义，页面只配置入口与行为，不各自重画或覆盖尺寸。
- 手机侧栏／抽屉也须重新核验密度：品牌区、分组留白、菜单行与账户区分别收紧；菜单正文独立滚动，关闭及末项可达，不将PC侧栏原样缩放。
- 同一底栏内不同含义的入口使用不同图标，跨页面同义入口复用同一定义。先区分内容主题与工具动作：AI产业消息须有AI主题辨识度，通用报刊图标不能区分栏目，AI助理／生成功能图标也不适合表示产业消息。优先使用清楚的业务图形，不退化成纯文字，也不用无含义装饰补足。
- PC 已有对应业务 SVG 时，手机入口复用该图标来源，只调整适配尺寸与笔画表现，不另换语义相同的图案；同时核验 PC／手机对应入口与同栏图标的实际视觉效果。
- 地域明确的股票市场可提取星形、条纹、圆点等国家特征元素，与K线等业务图形组合，并保留市场短名；这种组合须区别于正式国旗。股票入口的装饰性K线采用向右上升构图。
- 图标在手机实际尺寸下检查轮廓和视觉分量，避免把多个符号挤成需要猜测的图形。星形等填充面积较小的元素适度放大；大小、笔画、图文基线与选中底按实际效果校准，不能只令SVG宽高相同。X等熟悉的品牌图形保留辨识度，同时融入底栏的尺寸、颜色和选中态，避免单项突兀。
- 国旗等有正式规范的标识按权威图样核对比例、图案数量、位置及方向，缩小时保持图样完整，不把五星国旗简化成单星等近似符号。图标的色彩服从界面的SVG设计语言；采用单色时继承currentColor与选中态，同时保留准确图样，正式彩色展示则按权威颜色。
- 同项目、同层级的Tab优先复用已有视觉样式，用户明确保留的样式优先。区分选中、锚点定位与键盘焦点：内容定位不使用粗边框或外扩圆框包住大片正文，键盘焦点仍保留清楚的细致提示。
- 品牌标识在手机与PC缩放时保持相同轮廓；圆角随标识尺寸同比例调整，不能只沿用相同数值使小标识更圆。
- App 式固定顶部／底部工作区之间由内容区滚动，滚动条不覆盖导航；内容末项可达，切换工作区不会丢失业务状态。避免嵌套滚动容器阻断纵向滚动，横向图表操作也不能锁住页面滚动。
- 横向标签栏可用边缘小箭头提示并推进溢出内容，隐藏占位置的横向滚动条；箭头随可滚动方向显示，选中项自动露出，同时保留触摸滑动、鼠标拖动和键盘操作。不将此规则机械用于需要滚动条定位的图表或矩阵。
- 已有横向切换或侧栏筛选时，手机先适配原有机制；不要再叠加第二个横向滚动层或把筛选改成另一整页。隐藏重复滚动条只处理可见滚动条，不等于移除横向滚动或将单行标签改成换行。用户要求保留的导航和交互优先，具体默认开闭状态写入页面规格。
- 每次新建或修改有图表的页面，都检查左右轴区的字号与留白：刻度和价位标注采用较小字号，轴宽随实际标签收紧，不保留固定大边距；核验最长数字及边界不裁切。辅助刻度省去无用的小数尾零，低价或窄区间保留区分数值所需的小数，实际行情和结构化数据精度不随显示刻度舍入。
- 图表边框与坐标轴留在视口内，历史内容在图区内平移；图表高度按手机可视区域与阅读用途重新确定，不直接沿用桌面固定高度。成交量等辅助图区占较小比例，优先保证主图面积，不混同独立分析副图与成交量。
- 可滑动、平移的图表与矩阵同时支持触摸和鼠标拖拽，手机视口也不能只启用触摸。拖动与点击分开，保留正文纵向滚动，按两种输入实际验收；键盘、滚轮与滚动条按组件用途保留。
- 图表悬浮详情也需按手机设计：小字号、短标签、紧凑行距与边距，省去重复标题和长说明，保留日期、单位和关键数值精度。按触摸及指针核验宽度与位置，浮窗落在图表／内容可见范围内，不盖固定导航或大半张主图；桌面可以保留更完整文案。
- 图表头部的时间和动态数值按实际位数预留适度固定宽度，配合等宽数字，避免拖动或刷新时因数值长短改变而跳动；同时检查最大值与零值，不能用过大余量换取稳定。去掉挤窄图区的重复嵌套边框与内边距，同组图表保持一致的可用宽度；没有数据变化的非交易间隔可压缩为窄灰色分隔，保留时段边界。

## 网页 SEO 与分享预览（按需）

- 新建公开页面，或改动可索引正文、路由、初始 HTML、head 与分享卡片时，读取 [public-page-seo-assist](https://github.com/tsetsugekka/codex-sakura-account-site-skills/blob/main/skills/public-page-seo-assist/SKILL.md) 及与当前问题相关的参考资料；只改局部视觉样式且不影响这些契约时，不重复运行 SEO 流程。详细方法由该 Skill 维护，本文件保留制作页面时的触发条件与验收要求。
- 先确认公开／可索引范围，以及用户希望被搜索到的实际内容。文章、报告与排行的初始响应须包含约定的相关正文，不仅是产品简介；图表与计算工具不必嵌入全部历史。沿用适合项目的生成、内容更新或服务端渲染流程，保留权威数据源、初始内容与交互内容的归属；不以 `noscript` 代替正文交付验证，不因 JS 挂载丢失正文或显示重复内容。
- 初始 head 在应用与分析脚本之前输出 charset、唯一 title、description、canonical、OG／Twitter 与适当 robots；charset 靠近 head 开头。canonical、`og:url` 与最终路由一致，有 sitemap 条目时同时核对 `loc`；沿用项目语言与 favicon 约定，结构化数据匹配真实页面类型，不把数据工具当成文章。
- 区分行情／数据时间与真实发布时间；sitemap `lastmod` 仅在项目允许且已知实质内容修改时间时填写，未知时省略，不把部署或 cron 唤醒冒充内容更新。首访数据失败与刷新失败分别检查；按现行时效契约保留可用的有效快照并如实标记状态，不伪造数据或取消生成校验。
- 受保护页面只交付安全的路由级分享元信息，保留登录、API 授权及索引策略。分享图片应为可公开访问的代表图，尺寸如实，不能用私有图片或 favicon 冒充；文字卡片的兼容限制须明确。保留服务端维护的 HTML 标记及内容，按既有生成／发布流程更新。
