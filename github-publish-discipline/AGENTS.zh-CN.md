# GitHub 发布纪律

- 暂存或提交前用 `git branch --show-current` 确认分支，并检查工作区、暂存区及发布范围；只提交和发布本次任务内容，保留其他改动及其暂存状态。
- 无关文件、已有暂存内容、并行任务或同文件可分离的改动不构成阻塞；能安全隔离时，按文件、改动块或独立临时索引自动处理。独立提交后，只同步普通暂存区中本次已提交的改动，发布前复核实际提交与部署内容。
- 仅在实际冲突或范围不明确需要用户决定时询问，如不兼容的同处修改、不可分离的未完成依赖、无法安全整合的目标分支或覆盖受保护生产数据。先完成安全准备，再说明具体问题并一次性询问，不把潜在冲突当作已有冲突。
- 未经明确要求不创建、切换或推送新工作分支；若在旧临时分支，安全时将本次工作整合到既定目标分支，不沿用旧分支发布。临时分支合并且不再需要后，删除本地和远程副本。
- 遵守项目凭据、生产数据、发布范围和上线验证规则。内部维护文档不得上传公开站点。
