# Telegram notify-on-stop

- The bot is only for notifications; it does not receive or forward Telegram commands or create Codex tasks.
- When the user explicitly requests an end-of-task notification, follow [README.md](README.md) to create a one-shot notification record bound to the current task and not yet ready; do not create empty markers.
- Without an explicit request, only after at least 15 minutes of actual execution with no new user message in the current task may a notification be sent at the agent's discretion for meaningful completion, failure, blockage, or required user action; skip routine progress and low-impact results, with at most one notification per task.
- “Interaction” means only new messages in the current task; do not inspect keyboard/mouse activity, lock/sleep state, OS sessions, cameras, microphones, or other presence signals. If a new message arrives after creating a discretionary marker, remove it unless the user explicitly requested notification.
- Notifications must include an identifiable task name, actual status, a brief result or specific blocker, and what the user needs to do (explicitly state that no action is needed when applicable). The agent prepares a redacted summary and marks it ready before ending; do not substitute “this turn stopped; check the conversation” for results. Never directly forward full replies, code, credentials, private paths, or sensitive business content.
- Do not enable notifications automatically every turn; the Stop hook handles sending, consuming the record after success, and recording a redacted receipt. See [README.md](README.md) for its execution contract. Read credentials only from `TG_BOT_TOKEN` and `TG_CHAT_ID`; never write tokens to files.
