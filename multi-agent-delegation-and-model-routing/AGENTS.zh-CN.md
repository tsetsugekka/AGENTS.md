# 多 Agent 委派与模型路由

- 仅委派边界清晰、可并行且收益高于协调成本的独立子任务；明确输入、范围、约束、交付物、验收标准和编辑权限。数量与独立工作量相称，避免重叠探索。
- 每个文件或交付物设唯一负责人；未经协调所有权与合并方案，不并发修改同一文件。
- 委派时约定必要检查点和异常汇报：子 Agent 在完成、报错、阻塞或需要决策时主动通知，正常运行不发重复进度。主 Agent 优先处理独立工作并等待完成事件；确需检查状态时，按预期耗时与最近进展低频查询，无变化则拉长间隔，避免短间隔轮询或反复读取完整对话。
- 等待窗口结合模型、思考档位和任务类型确定：Luna 的批量后台工作、Sol 的高推理或多步骤任务应留足执行时间，不仅因暂无输出或单次等待超时就催促、打断或重派。只在新增约束、到达约定检查点、明显超出预期或出现异常证据时定向联系。
- 主、子 Agent 从以下八种模型与思考档位组合中选择，保留性价比拐点及独特能力用途，不为所有中间档安排任务；这些组合按用途分工，不构成统一的高低阶梯：
  - `gpt-6-luna low`：少用，仅用于真正单调、执行规则完整且不赶时间的机械后台任务；完全确定的处理优先用现成命令或脚本。
  - `gpt-6-luna high`：规则明确、需要少量判断的重复后台工作，不默认用于用户正在等待的连续前台交互。
  - `gpt-6-luna max`：规则与验收明确、仍需逐项判断的批量后台工作，例如半结构化内容提取、归类、核对和重复修改。
  - `gpt-6.1-sol low`：用户正在等待的简单任务、小范围明确操作及已知页面上的连续 Computer Use；不因任务机械就固定交给 Luna。
  - `gpt-6.1-sol medium`：日常开发与分析主力，负责明确的代码实现、测试结果分析、局部故障定位及需要判断的交互操作。
  - `gpt-6.1-sol xhigh`：确实需要更强技术推理或更高交付质量的困难开发、复杂根因、冲突证据综合与验证审查，不作为日常默认。
  - `gpt-6-astra low`：需要把握隐含意图、措辞、语气和细微含义并保持原意的处理，以及短范围创意讨论；不替代普通内容整理。
  - `gpt-6-astra high`：复杂综合目标、规划与委派、整体审查，以及创意或审美要求较高的工作；不因任务包含规划或终审就固定调用。
- Astra 偏综合理解、意图与创造性判断，Sol 偏明确的技术执行；这是用途偏好，不是绝对能力分界。不仅因综合 benchmark 接近就认为 Sol 可替代 Astra，也不把普通任务都转给 Astra。
- 在满足质量与权限要求的组合中，兼顾成本和实际完成时间；收益不足以抵偿成本的档位不纳入常用路由。按已知难度和歧义直接选档，无须先让低档失败；能力不足或实际延迟明显影响交付时及时调整。Luna 优先用于不阻塞主流程的后台工作，不仅因便宜就让用户等待；不为小任务额外委派或终审。上下文长度、重要性、步骤数或单一 benchmark 不单独决定选择。
- `gpt-6-astra xhigh` 及以上仅在用户明确选择或授权时使用，主、子 Agent 不自行升档或新开该档子 Agent；Astra low/high 可按任务自主选择。
- 子 Agent 成果须由主 Agent 结合实际文件、来源和适当验证复核；主 Agent 负责范围、整合、冲突、最终交付，并将阻塞或授权需求汇总为一个清晰请求。委派不扩大操作权限。
