# Multi-agent delegation and model routing

- Delegate only independent subtasks with clear boundaries that can run in parallel and offer more benefit than coordination cost; define inputs, scope, constraints, deliverables, acceptance criteria, and editing permissions. Keep the number of agents proportional to independent work and avoid overlapping exploration.
- Assign one owner to each file or deliverable; do not edit the same file concurrently without coordinating ownership and a merge plan.
- Agree on necessary checkpoints and exception reporting when delegating: sub-agents proactively report completion, errors, blockers, or decisions needed, without repetitive progress messages during normal execution. The primary agent prioritizes independent work and waits for completion events; when a status check is necessary, check infrequently according to expected duration and recent progress, lengthening the interval when nothing changes. Avoid short-interval polling or repeatedly reading entire conversations.
- Set waiting windows according to the model, reasoning effort, and task type: allow enough execution time for Luna batch background work and Sol tasks with high reasoning effort or multiple steps. Do not urge, interrupt, or reassign work merely because there is no output yet or a single wait times out. Contact the relevant agent only when there are new constraints, an agreed checkpoint is reached, execution clearly exceeds expectations, or evidence of an exception appears.
- Primary and sub-agents choose among the following eight model and reasoning-effort combinations, retaining combinations at useful cost-performance tradeoffs and those with distinct capabilities rather than assigning tasks to every intermediate level. These combinations serve different purposes rather than forming a single low-to-high hierarchy:
  - `gpt-6-luna low`: use sparingly, only for truly monotonous mechanical background tasks with complete execution rules and no time pressure; prefer existing commands or scripts for fully deterministic processing.
  - `gpt-6-luna high`: repetitive background work with clear rules and a small amount of judgment; not the default for continuous foreground interaction while the user is waiting.
  - `gpt-6-luna max`: batch background work with clear rules and acceptance criteria that still requires judgment on each item, such as semi-structured content extraction, classification, checking, and repetitive edits.
  - `gpt-6.1-sol low`: simple tasks while the user is waiting, small clearly specified operations, and continuous Computer Use on known pages; do not automatically assign a task to Luna merely because it is mechanical.
  - `gpt-6.1-sol medium`: the main choice for everyday development and analysis, including clearly specified code implementation, test-result analysis, localized fault diagnosis, and interactive operations requiring judgment.
  - `gpt-6.1-sol xhigh`: difficult development, complex root causes, synthesis of conflicting evidence, and verification reviews that actually need stronger technical reasoning or higher delivery quality; not the everyday default.
  - `gpt-6-astra low`: work that requires understanding implicit intent, wording, tone, and subtle meaning while preserving the original meaning, as well as creative discussion of limited scope; not a substitute for ordinary content organization.
  - `gpt-6-astra high`: complex combined goals, planning and delegation, overall review, and work with substantial creative or aesthetic requirements; do not automatically select it merely because a task includes planning or final review.
- Astra favors integrated understanding, intent, and creative judgment; Sol favors clearly specified technical execution. This is a preference by purpose, not an absolute capability boundary. Do not assume Sol can replace Astra merely because their aggregate benchmarks are close, or send all ordinary tasks to Astra.
- Among combinations that meet quality and authorization requirements, consider both cost and actual completion time; exclude levels whose benefits do not justify their cost from routine routing. Choose directly based on known difficulty and ambiguity, without requiring a lower level to fail first; adjust promptly when capability is insufficient or actual latency materially affects delivery. Prefer Luna for background work that does not block the main workflow, and do not keep the user waiting merely because it is cheaper; do not add delegation or a final review for small tasks. Context length, importance, step count, or a single benchmark do not decide the choice on their own.
- Use `gpt-6-astra xhigh` or higher only when the user explicitly selects or authorizes it; primary and sub-agents must not independently increase to that level or start a new sub-agent at that level. Astra low/high may be selected autonomously according to the task.
- The primary agent must review sub-agent results against actual files, sources, and appropriate verification; it owns scope, integration, conflicts, and final delivery, and consolidates blockers or authorization needs into one clear request. Delegation does not expand authority.
